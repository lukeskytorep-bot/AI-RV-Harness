# Fixed-lead telepathy — candidate implementation

11 October 2026. Candidate on the user-supplied green `ai-rv-2` source, not a published release or completed desktop acceptance. Application version remains 0.7.13 and schema remains 031.

New Training and Conversation series freeze `fixed_lead_v1`, a selected lead, the instruction text/version, participants, personal read-only learning, routes and three-cycle limit. Geography is locally shuffled from the versioned 48-entry PL/EN pool and assigned to all rounds before provider dispatch. A fixed lead does not imply a fixed target: every round creates and locks its own target. Legacy records without the marker preserve their existing round semantics and can Resume final reflections explicitly.

After the initial descriptions, the lead may finish immediately or issue up to three decisions. A decision can address a group or individual receivers and finish a receiver early. Its validated decision is persisted before dispatch. Per-cycle recipient scopes and saved successful responses allow Resume to recover a partially delivered cycle. Questions expose only the addressed instruction and the receiver's own previous text. Target and geography remain in the lead packet. Explicit known geography/full-target leaks are rejected; this is not a proof against semantic disclosure.

AI reflections run after Reveal, with receivers before the lead summary. The lead sees current-round answers and reflections. Receivers choose whether to receive others' statements. Human reflection, consent and sharing comments are human actions. Finalization has its own durable state and does not reopen completed rounds. Opening history never calls a model. Stop combines user cancellation with lease loss and prevents subsequent stages; provider cancellation can leave an uncertain dispatch that requires operator resolution.

The existing fenced `plan_json` stores `_runtime.version=1`, round guidance, supplementary blind text, transcript, per-call usage/elapsed time and finalization/archive fields. Existing relational rows remain authoritative for their existing columns. `persistence.ts` reconstructs the extension on SQLite reads. Browser storage retains the same fields. An archive revision predicate in the registered TS and Rust series UPSERT prevents an older snapshot from undoing an archive/restore. No migration was added; migrations 001–031 are byte-identical to the input ZIP.

Actual receiver descriptions/reflections use the shared completeness classifier. Descriptive stages prefer 16K and then 32K, within model limits; short target/decision/consent stages remain 4K. Partial output is diagnostic, never sealed evidence. Persistent failed attempts exhaust after two; uncertain dispatch never retries automatically. Capacity is checked against the actual packet, including frozen learning. Catalog pricing is not a start blocker. Costs with no provider report remain explicitly incomplete; no estimated bill or financial authorization is introduced. Request time is the sum of recorded call durations and excludes pauses. Reasoning tokens are not added again to total tokens.

`TelepathicTranscript` isolates Markdown records, orders the lead first, and keeps participant links/back navigation. Conversation uses a role-aware data projection, including hidden geography/category and hidden lead/other-receiver text before Reveal. Training is an observer surface. Shared history starts open and provides Open, Save and Archive/Restore. Settings Archive and recovery includes telepathy restore; permanent deletion was not extended. Native export copies authorized attachments with relative links; browser export downloads Markdown. Both use the role-safe transcript projection. Old missing prompts are marked, never reconstructed.

Owners: `leadGuidance.ts` (decision contract and adapted Monitor), `fixedLeadRuntime.ts` (cycle checkpoints), `geography.ts`, `persistence.ts`, `transcript.ts`, `stageLabels.ts`, `runtimeMetrics.ts`, `archive.ts`, pure `telepathicExchange/export.ts`, and `exports/telepathy.ts` (file writing). Shared TooltipButton was extracted with unchanged positioning behavior from standard Training.

Acceptance is open: local frontend/SQLite/DOM gates passed, but Rust, OpenRouter cross-language bridge and actual visual desktop/browser smoke could not run in this environment. See the implementation report for exact evidence and remaining checks.


## Post-audit boundaries

A rejected archive-revision parent upsert raises a native transaction error before child writes in both ordinary and fenced batches. Missing revision means zero. Lead JSON is domain-validated before the provider ledger accepts success; diagnostic failures consume durable attempts. The scope fingerprint includes resolved generation and endpoint/model routing, excluding only the scheduled per-attempt output escalation. Each call retains resolved request settings. Resume rejects drift before dispatch; accepted results replay without resolving new settings. Legacy transcript projection adapts stored responses and final reflections under the existing visibility policy, without inventing prompts. Archive human/recovery actions fail under lease. Metrics report known subtotals and missing coverage; Conversation polls only its safe projection during execution. See the post-audit Polish report for validation and pending native/visual acceptance.
